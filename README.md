# TICKER FRONT — MVP

**▶ 플레이: http://defense.juganlab.com/**

정체를 가린 **실제 과거 국내 주식 차트**(일봉, 1봉 = 1거래일 = 게임 1초)를 읽어 전쟁 자금을 만들고, 그 돈으로 일자형 타워디펜스 13웨이브를 막아 지역을 점령하고, 클리어 후 그것이 **어떤 회사의 어느 시기였는지** 알게 되는 게임. 스테이지 하나 = 실제 390거래일(약 1년 7개월)의 장세. (PRD: `PRD_TICKER-FRONT_MVP.md`)

## 요구 사항

- Node.js 20+
- Python 3.11+ (`pip install -r pipeline/requirements.txt` — 데이터 수집용)

## 실행

```bash
npm install
pip install -r pipeline/requirements.txt

# 1) 데이터 수집 (최초 1회, ~1분) — yfinance로 국내 주식 30종목 × 일봉 10년치
npm run fetch

# 2) 데이터 빌드 — 390거래일 윈도우 슬라이싱, σ/이벤트/아키타입 계산, 블라인드 bars 파일 생성 (~890조합)
npm run build:data

# 3) DB 시드
npm run seed

# 4) 실행 (server :3000 + web :5173)
npm run dev
# → http://localhost:5173
```


## 예측 시스템 (선물식 자유 진입·청산)

만기 없이 LONG/SHORT **진입·청산 시점이 자유**다 (FR-5). 체결은 진입·청산 모두 **요청 순간 화면에 보이는 보간 가격 즉시 체결** — 서버가 자기 시계로 동일 보간식을 재현해 산출한다 (서버 권위, 클라 신고가 불사용). 손익은 연속: `payout = stake × (1 + clamp(g≥0 ? 0.9g : L·g, −0.95, 2.7))`, `g = 방향×Δ%/σ30 ×배율`. 하방 계수 L(R1 0.7 / R2 1.05 / R3 1.7)은 실데이터 |g| 분포로 손익분기 승률을 PRD §9.1 목표에 맞춰 역산했다.

| 기능 | 내용 |
|---|---|
| 거래 횟수 | 스테이지 시작 **10회**, 웨이브가 넘어갈 때마다 **+2** (13웨이브 기준 34회). 리서치 데스크로 추가 확장 |
| 수수료 | 명목가(스테이크 × 배율)의 **2%**를 진입·청산 각각 AUM에서 차감. 배율을 올리면 수수료도 비례해 늘어난다 |
| 손절 · 익절 | **차트를 드래그**해 가격 레벨 지정. 진입가 위=익절, 아래=손절. 라벨에 그 가격의 실현 손익 표시, ×로 해제. 판정은 서버가 하며 **봉의 꼬리(고가·저가)가 스쳐도 체결**된다 |
| 레버리지 | 기본 1×, 마진 데스크로 3×·5× 해금 (손실은 MAX_LOSS_RATE에서 클램프) |
| 이동평균선 | MA 5·20·60 토글. **현재 봉까지만** 계산해 미래 정보가 새지 않는다 |
| 마진콜 | 미실현 손실이 상한에 닿으면 서버가 즉시 전액 청산 |

**경제 루프 (FR-5.5b)**: 진입 시 AUM에서 스테이크 차감 → 청산 시 **스테이크(−손실)는 AUM으로 반환**되고 **순수익만 골드로 환전**(1건당 500G 상한, 초과분은 AUM). 여기에 **적 처치 시 유형별 `aumBounty`만큼 AUM 회복**(초기 AUM×0.2 상한). 전투 성과가 트레이딩 자본을 되채우는 순환.

**승패 (FR-6.9/6.10/6.11)**: 승리 = 13웨이브 방어 완료 **또는 적 본진(600 HP) 파괴**. 패배 = 사옥 HP 0 **또는 파산**(AUM 소진 + 무포지션). 적은 사옥을 통과해 사라지지 않고 **그 자리에서 사옥을 계속 때린다** — 죽이지 않으면 무너진다.

## 난이도 (FR-2.6)

스테이지 진입 전 **이지 / 하드**를 고른다. 차트와 트레이딩 규칙은 같고 방어전의 압박만 다르다.

| | 적 체력 | 적 공격력 | 적 수 | 자본금 보상 |
|---|---|---|---|---|
| 하드 | ×1.7 | ×1.7 | ×1.0 | 100% |
| 이지 | 하드의 50% | 하드의 55% | 하드의 75% | 70% |

## 전투 설계 (레퍼런스 기반)

| 메커니즘 | 레퍼런스 | 구현 |
|---|---|---|
| 방어구/마법 이분법 | Kingdom Rush | 물리는 armor에 감소, 마법(옵션 스파이어·지정가 Lv2 철갑탄)은 armor 관통·mr에만 감소 |
| 타겟팅 모드 | Bloons TD | 포탑 클릭 → 선두/후미/강적/근접 순환 |

| 포탑 슬롯 | — | 사옥 탑재 2칸 + 지면 칸(시설팀 1~3) + 점령 보상, 최대 6. 배치 모드에서만 점선 표시 |

| 유닛 스킬 | — | 평타 N회마다 자동 발동, 스프라이트의 **타격 프레임에 판정**(모션 도중 발사 방지). 넉백·기절·둔화·출혈·보호막·표식 등 |
| 적 8종 | Kingdom Rush 적 다양성 | 창 망령 / 석궁 사수 / 다연장 포병 / 방패 파쇄병 / 확성기 드론(공중·버프) / 연 정찰기(공중·표식) / **번개 왕**(중간 보스 W7) / **드릴 워커**(최종 보스, 마지막 웨이브) |
| 적 스킬 | — | 근접·사격형은 **교전 누적 N회**로, 포병·정찰기·보스는 주기+사거리로 발동 |
| 위기 반격 | — | 적 본진이 40%/20% 밑으로 떨어지면 정예 분대 투입 + 충격파로 아군을 중원까지 밀어낸다 |

**밸런스 측정** (봇 시뮬 40회/셀, 승률 45~65%): 이지 R1 38~70% / R2 35~65% / R3 10~55%, 하드는 R1 0~8%. **예측 미실시 시 전 지역 0%** (§9.3 코어 보증).
봇은 고정 빌드·고정 소환 주기로만 플레이하므로 **하드 수치는 하한**으로 읽어야 한다 — 사람이 잘 하면 훨씬 여유가 있다.

## 회사 (부서 8종)

스테이지 정산으로 받은 자본금으로 영구 강화한다 (환불 없음, 효과는 합연산).

| 부서 | 효과 (Lv1 → Lv3) |
|---|---|
| 트레이딩 데스크 | 초기 AUM 2,000 → 2,800 |
| R&D | 타워 피해 +0% → +16% |
| 인사팀 | 유닛 HP +0% → +20% |
| 법무팀 | 손실률 −0.00 → −0.10 |
| IR팀 | 정산 보너스 +0% → +10% |
| 마진 데스크 | 레버리지 최대 1× → 5× |
| 리서치 데스크 | 스테이지당 거래 +0 → +10회 |
| 시설팀 | 지면 포탑 슬롯 1 → 3칸 |

## 도감 (FR-10)

클리어한 차트가 기록된다. 카드에는 **어느 지역·난이도**였는지, **실제 차트 구간**(시작일~종료일), 그 구간의 **실제 종가 곡선**, 그리고 그때 낸 **적중률·수익률·등급**이 함께 남는다.
