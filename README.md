# TICKER FRONT — MVP

정체를 가린 **실제 과거 국내 주식 차트**(1분봉)를 읽어 전쟁 자금을 만들고, 그 돈으로 일자형 타워디펜스 13웨이브를 막아 지역을 점령하고, 클리어 후 그것이 **어떤 회사의 어느 날이었는지** 알게 되는 게임. (PRD: `PRD_TICKER-FRONT_MVP.md`)

## 요구 사항

- Node.js 20+
- Python 3.11+ (`pip install yfinance` — 데이터 수집용)

## 실행

```bash
npm install

# 1) 데이터 수집 (최초 1회, ~3분) — yfinance로 국내 주식 30종목 × 최근 20거래일
npm run fetch

# 2) 데이터 빌드 — 390봉 정제, σ/이벤트/아키타입 계산, 블라인드 bars 파일 생성 (~600조합)
npm run build:data

# 3) DB 시드
npm run seed

# 4) 실행 (server :3000 + web :5173)
npm run dev
# → http://localhost:5173
```

## 검증 도구

```bash
npm run test   # 판정·정산·수입분배·전투 단위테스트 (PRD 수용 기준)
npm run sim    # 봇 시뮬레이터 — 승률별 클리어율을 §9.3 설계 곡선과 대조
npx tsx server/scripts/calibrate_pnl.ts  # 데이터 재수집 후 하방 계수(L) 재캘리브레이션
```

## 구조

```
shared/    타입 + 밸런스 상수(§9) + 판정/정산 수식 + 전투 엔진 (서버·클라·봇 공유)
pipeline/  오프라인 데이터 배치 (§10): fetch_krx.py → build.py
server/    Express REST(§7.1) + WS 판정 엔진(§7.2~7.3, 서버 권위) + SQLite(§6.1)
web/       Vite+React: 인트로/튜토리얼/지도/스테이지/공개 연출/도감/회사
```

## 전투 설계 (레퍼런스 기반)

| 메커니즘 | 레퍼런스 | 구현 |
|---|---|---|
| 방어구/마법 이분법 | Kingdom Rush | 물리는 armor에 감소, 마법(광역 포탑·공시폭탄)은 armor 관통·mr에만 감소 |
| 타겟팅 모드 | Bloons TD | 타워 클릭 → 선두/후미/강적/근접 순환 (힐러는 강적 타겟팅으로 저격) |
| 유닛 역할 조합 | Age of War | 인턴=블로커(3기 저지, 초과 통과) / 애널리스트=원거리(대공 50%) / 트레이더=근접 2체 광역 |

| 전투 정보 | — | 준비 페이즈 웨이브 조합 미리보기, 사거리 원, 투사체·데미지 숫자·사망 연출 |

밸런스는 봇 시뮬레이터 기준 (FR-5.5b 정산 분해 + 처치 AUM + 조기 승리 반영): R1 52→85%(승률 따라 상승) / R2 47→67% / R3 27→47%(p<50% 실력 게이트) / **예측 미실시 시 전 지역 0%** (§9.3 코어 보증).

## 예측 시스템 (선물식 자유 진입·청산)

만기 없이 LONG/SHORT **진입·청산 시점이 자유**다 (FR-5 개정). 체결은 진입·청산 모두 요청 다음 1분봉 종가 (서버 권위). 손익은 연속: `payout = stake × (1 + clamp(g≥0 ? 0.9g : L·g, −0.95, 2.7))`, `g = 방향×Δ%/σ30`. 하방 계수 L(R1 0.7 / R2 1.0 / R3 1.7)은 실데이터 |g| 분포로 손익분기 승률을 PRD §9.1 목표(40.5/45.4/50.2%)에 맞춰 역산했다. 보유 중 미실현 손익이 실시간 표시되고, 스테이지 종료 시 미청산 포지션은 마지막 봉 종가로 강제 청산된다.

**경제 루프 (FR-5.5b)**: 트레이딩은 AUM 공간에서 — 진입 시 AUM에서 스테이크 차감 → 청산 시 **스테이크(−손실)는 AUM으로 반환**되고 **순수익만 골드로 자동 환전**(1:1)된다. 즉 손실은 AUM에서 깎이고, 이익은 골드로 들어온다. 여기에 **적을 처치하면 유형별 `aumBounty`만큼 AUM이 회복**된다 (FR-6.8b — 본진에 도달한 적은 제외, 서버가 초기 AUM×0.2 상한으로 clamp). 전투 성과가 트레이딩 자본을 되채우는 순환.

**승패 (FR-6.9/6.10)**: 승리 = 13웨이브 방어 완료 **또는 적 본진 파괴(즉시 승리)**. 패배 = 본진 HP 0 **또는 파산**(AUM 소진 + 무포지션).

## PRD 대비 구현 노트

| 항목 | 상태 |
|---|---|
| 데이터 | 국내 주식 실데이터 (yfinance, **최근 30일 한정** — 역사적 날짜는 증권사 API 필요, 향후 과제) |
| DB | PostgreSQL → SQLite (로컬 MVP, 스키마는 §6.1 동일 구조) |
| 뉴스 헤드라인(FR-9 3단계) | 데이터 소스 미확보로 비어 있음 — 있으면 표시, 없으면 자동 생략 |
| 블라인드(FR-4) | 페이로드·URL에 종목/날짜 없음, 불투명 UUID. 가격 절대값 포함 여부는 오픈 이슈 O-3 |
| i18n 키 분리(FR-13.4) | 생략 (한국어 하드코딩) |
| R2·R3 웨이브 테이블 | 봇 시뮬 기준 튜닝 완료, 최종 스펙은 플레이테스트로 확정 (PRD §9.4) |

토큰 유실 시 진행도 복구는 지원하지 않습니다 (FR-1.4, localStorage `tf.token`).
